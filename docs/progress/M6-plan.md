## Risks
- **Size**: 14 pages + ~70 endpoints. Waves keep agents resumable; wave A = everything collect/org/settings, wave B = content/governance. Lead may split wave B further (content+impact+migration / follow-up+privacy+reports+health).
- New npm deps need network (`exceljs`, `tiptap`, `dnd-kit`); `pnpm install --offline` in worktrees will miss them until one online install populates the store — lead installs once on main checkout first.
- Builder is the most complex UI (nested repeaters, rule builders); keep repeater child editing one level deep (matches definitions).
- KPI constants → `kpi_definition` table touches public impact code paths (M1/M5 pages): regression-test `/impact`, Home tiles, programs, district.
- UI-string overrides interact with Cache Components caching of messages; if risky, ship read/edit + apply on next build (TODO noted in log).
- Privacy erase is destructive by design: confirm dialog, audit counts only, tests on mock + db.
- Follow-up phones are stored raw (field encryption still an open issue from M2); reveal path must never be cached (`cache: 'no-store'`, no RSC prefetch).
- Hindi strings agent-written → native review backlog.
