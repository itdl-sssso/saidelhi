Root cause: not the redirect cache, DB, or proxy (the 301 answers in 50-300 ms). The test waited for networkidle on /admin/migration?tab=redirects. With a query string in the URL, the sidebar link prefetch for the same path without query (/en/admin/migration?_rsc=..., 307, 307, /admin/migration?_rsc=...) returns 200 with x-nextjs-postponed: 2 and chunked encoding, but the body is never completed; the browser aborts it at about 29.5 s (net::ERR_ABORTED). Playwright counts it as in flight, so networkidle fires 500 ms after the abort (31.1 s). Reproduced on /admin/centres?x=1 and /admin/people?tab=x; plain URLs without query do not hang. Plain curl and in-page fetch replays of the same chain finish in about 10 ms, so the hang is in the browser prefetch body, not the server render. Possible app-side follow-up: same-path prefetch on queried portal URLs.
